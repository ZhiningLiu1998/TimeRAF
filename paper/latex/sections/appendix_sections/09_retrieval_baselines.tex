\section{Retrieval comparisons and controls}
\label{app:retrieval-baselines}

The matched fixed-forecast comparison spans the same 585
backbone--dataset--horizon cells for every method. \raft{} uses multiscale
Pearson retrieval and softmax aggregation~\citep{han2025raft}; \saraf{} adds
time alignment, stationarity-controlled relevance--diversity selection, and
Gaussian aggregation~\citep{zhou2026saraf}. These rows evaluate retrieval
operators on common base forecasts, not the original learned forecasting
or fusion layers.

\analogknn{} transfers a normalized historical future, whereas \residualknn{}
transfers the corresponding error from the same base model; in the notation of
Equation~\ref{eq:dial} they pin $\beta=1$ and $\beta=0$. The full \method{} row
selects $\beta$, the horizon profile, and the alternative simple corrections on
validation. All methods select parameters on the same chronological validation
suffix; retrieval memory ends at least one horizon earlier, and prediction APIs
receive no test labels. The \method{} row was produced by a later run than the
comparison systems; its error-only configuration reproduces the earlier run's
selected candidate in all 585 cells and every strict-win classification, with a
maximum relative metric difference of $1.6\times10^{-5}$ from thread-level float
reordering, so the rows remain paired cell by cell.
Tables~\ref{tab:retrieval-long-term-values}--%
\ref{tab:retrieval-short-values} give the per-backbone absolute errors and
paired deltas behind main Tables~\ref{tab:main-long-term}
and~\ref{tab:main-short-term}, including the PEMS RMSE column omitted there.
The accompanying machine-readable results retain all 585 per-cell records, so
duplicating them as 90 multi-page tables is unnecessary.
